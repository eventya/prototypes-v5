Matricea de test pentru staging

Fiecare rând se încearcă de mână și se bifează când rezultatul văzut e cel așteptat. Lansarea plăților așteaptă o matrice verde. Bifele se țin doar în browserul tău.

Ce are staging-ul
  • Stripe în test mode, cu cheile și webhook secret-ul de staging din 1Password. Nicio cheie live. billing.stripe_enabled e pornit.
  • Local, Stripe CLI: stripe listen --forward-to localhost:3000/stripe/webhooks. Pe staging, webhook-ul de test e setat în Stripe spre /stripe/webhooks.
  • Test clocks pentru reînnoiri, grație și anulări. Stripe leagă un Customer de un test clock doar la creare, deci Customer-ul de test se creează direct pe ceas.
  • Template-urile copiate din producție, toate 7.
  • Utilizatori de test: unul nou, unul cu spații, unul doar membru public, unul cu un spațiu suspendat, un admin @eventya.net.

Regulile ecranului
Când se foloseșteLa etapa „testare” a fiecărui feature din storyboard, pe grupele lui. Înainte de lansarea plăților, o trecere completă.
Doar test modePe staging nu există chei live. Plata reală cu un card intern se face o singură dată, în producție, la lansare, și se rambursează.
Ceasul nostruUn test clock mută doar timpul din Stripe. Joburile noastre (PAY-002 în zilele 3 și 6, suspendarea după grație, SUB-001) rulează pe ceasul serverului, deci se pornesc de mână, cu data mutată.
FacturileNu se emit din aplicație. Pe staging se verifică doar că PAY-006 pleacă o dată, cu datele corecte ale cumpărătorului.
Un defect găsitSe deschide un tichet cu numele rândului. Rândul rămâne nebifat până la reparație și reverificare.
BifeleÎn localStorage, cheia proto-onboarding-checks. „Resetează bifele” le șterge pe toate, pentru o trecere nouă.
